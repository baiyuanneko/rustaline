# 后台设置与邮件提醒

登录 `/admin/` 后打开「设置」，可以调整评论规则、验证码和 SMTP 邮件提醒，保存后下一次请求立即使用新设置。

## 从旧版本升级

首次启动新版时，应用自动创建业务设置表，并把当前有效的 `config/default.toml`、`config/local.toml` 和 `APP_*` 评论配置写入数据库。默认部署使用同一个 SQLite 文件，已有评论与管理员账号保留。

数据库有业务设置后，后台保存的值始终优先。原来的评论和邮件环境变量只用于首次初始化，之后修改它们再重启不会覆盖后台设置。新增配置字段自动使用默认值，邮件默认关闭。

数据库地址、Redis 地址、JWT 密钥、日志、静态目录、首页与 Swagger 启动开关，以及验证码 HMAC 密钥仍由文件/环境变量控制。SQLite、PostgreSQL、MySQL 使用相同的迁移和设置接口。

升级前停止应用并备份数据库和部署配置。需要回退时，先保留一份升级后的完整数据库，再恢复升级前的数据库备份与对应旧版程序/配置；升级后产生的评论需要另行保留和迁移，不能直接覆盖丢弃。

旧二进制的迁移器不认识新增迁移记录，不能直接连接升级后的数据库启动。新版后台修改也不会回写旧配置文件。不要通过手工删除迁移记录来规避检查，也不要在唯一的数据副本上执行向下迁移。

## 评论与验证码

- 评论审核、最大正文长度、默认昵称、头像 CDN 和评论者环境摘要都可以在后台调整。
- 每 IP 每分钟提交上限为 `0` 时拒绝所有评论提交。
- PoW 与图形验证码独立开关，同时开启时必须通过两者；默认都开启。
- 验证码有效期最多一年，启用时必须大于零；常用默认值为 PoW 十分钟、图形码五分钟。
- 已打开页面会在提交前重新获取验证码和正文长度设置，网络错误或校验失败时保留草稿，重试即可。

## 配置 SMTP

1. 填写 SMTP 服务器、端口、加密方式、账号与密码，发件邮箱应是 SMTP 服务允许的地址。
2. 按服务商要求选择 STARTTLS（通常端口 587）或 TLS（通常端口 465）；无加密模式用于受控的本地中继。
3. 填写站点名称、站点地址和邮件语言，打开需要的提醒开关。
4. 启用 SMTP 并保存，再填写测试收件地址发送测试邮件；测试使用已经保存的配置。

没有认证的中继可以不填账号和密码。密码框留空表示保留已有密码，输入新密码表示替换，清除按钮表示明确删除；密码不会回显到浏览器。

SMTP 密码以加密形式保存到数据库，密钥从 `APP_JWT_SECRET` 独立派生。更换 JWT 密钥后，邮件发送暂停，后台会提示重新填写 SMTP 密码；其他设置和评论功能仍可使用。

## 两种提醒

**管理员新评论提醒：** 新提交的顶层评论和回复都会通知管理员，包含待审核评论。管理员收件地址由后台配置。

**评论者回复提醒：** 只通知直接被回复的评论者，且回复已公开、父评论存在、填写了有效邮箱并开启接收提醒。评论者可以在 SDK 表单取消「接收回复邮件」，回复自己的邮箱不会发送提醒。

待审核回复在通过审核后发送。旧评论、Valine 导入、蜜罐拦截和重复审核不会产生历史邮件或重复入队。

邮件发送在后台队列执行，SMTP 故障不会阻塞评论提交。失败最多尝试五次，重试间隔为 30 秒、2 分钟、10 分钟、30 分钟；待发送任务在重启后继续处理，最近状态可在后台查看。邮件服务接受邮件后、应用记录成功前发生崩溃时仍有可能重复投递，固定 Message-ID 可帮助邮件服务识别重复。

## 并发修改

后台保存使用版本号保护。如果其他页面已保存更新，当前页面会提示冲突，请重新载入设置后再编辑，避免覆盖刚保存的配置。
