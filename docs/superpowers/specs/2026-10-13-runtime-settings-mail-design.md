# 后台业务设置与 SMTP 邮件提醒设计

状态：用户已批准（2026-10-13），按本设计继续实施。

## 目标与已确认范围

- 后台可以调整评论规则、PoW 和图形验证码设置，保存后即时生效，重启后保持。
- 将这些业务设置迁入项目现有数据库；默认部署使用 SQLite，继续使用 Sea-ORM 和跨库迁移，保留 PostgreSQL/MySQL feature。
- 新版本首次启动自动接纳旧版本 TOML、local.toml、APP_* 的有效业务配置，已有评论与管理员账号不受迁移影响。
- 支持 SMTP 邮件发送，管理员新评论提醒和评论者回复提醒分别开关；用户已确认两种提醒都需要。
- 设置页提供配置保存、密码保留/替换/清除、发送测试邮件和最近发送状态。

## 方案选择

采用“启动参数留在文件/环境变量，业务设置入库”的方案。

继续改文件并重启不能满足后台即时调整；把所有配置入库则会让数据库连接和 JWT 密钥的加载依赖数据库本身。业务设置入库能够满足需求，并沿用现有部署入口。

本次迁入数据库的设置：

1. 评论审核、最大正文长度、每 IP 每分钟提交上限、默认昵称、头像 CDN、是否显示评论者环境摘要。
2. PoW 开关、难度、有效期，图形码开关、有效期、错误次数，PoW 是否绑定 IP。
3. SMTP 开关、主机、端口、加密方式、用户名、密码、发件地址/名称、管理员收件地址、两种提醒开关、站点名称/地址、邮件语言。

服务器地址、数据库/Redis 连接、JWT 密钥与有效期、黑名单开关、日志、静态文件目录、演示首页/Swagger 启动开关，以及验证码 HMAC 密钥继续由部署配置负责。已有后台响应中的 version、introduction_index、swagger_ui 保持兼容。

## 数据库与新旧版本迁移

新增按日期命名并注册的迁移，不修改已经发布的迁移文件。

- `app_settings`：单条记录（id = 1），schema_version、revision、业务设置 JSON TEXT、SMTP 加密密码、created_at、updated_at。
- `mail_jobs`：持久待发送任务，id、唯一 event_key、通知类型、关联评论/父评论 id、收件人、状态、尝试次数、下次尝试时间、领取令牌与租约时间、简化错误类别、创建/更新时间。
- `comments.reply_notification`：回复提醒偏好，默认 true；旧记录和旧客户端保持“填写邮箱即可接收回复提醒”的兼容行为。Valine 的 isNotified 继续表示发送状态，不能充当接收偏好。

启动顺序：加载部署配置 → 校验 JWT → 连接数据库 → 自动迁移 → 读取/首次播种业务设置 → 校验实际生效的业务设置 → 管理员种子 → Redis → 路由与邮件任务。

首次播种时使用当前旧配置加载器计算出的 comment 设置；同一事务中插入单行记录，冲突时读取已有记录，避免多个实例启动互相覆盖。SMTP 默认关闭。增加可选的旧式文件/环境变量 SMTP 配置用于首次播种，无此配置的旧部署也能够正常升级。

数据库中有记录后，迁入库的 TOML/APP_* 只作为首次初始化来源，重启不能覆盖后台保存结果。新增字段通过 schema_version 和 serde 默认值进行向前迁移，并在文档中明确该优先级。未识别的未来 schema_version 拒绝静默重写。

数据库迁移只新增表/列，不重建评论数据，不修改已有管理员凭据。旧二进制忽略新增设置表，仍使用原来的部署配置；因此保留旧配置文件可以回退运行，但新版后台修改不会自动同步回旧版本文件。

## 生效方式与接口

保留不可变 AppConfig 作为启动配置；业务请求经设置服务读取数据库快照。一个请求共享同一份快照，限流、验证码与提交规则不会在请求中途分别读到不同版本。读取共享数据库也使多个应用实例在下一次请求看到相同设置。

设置服务负责数据库访问、首次播种、版本升级、参数校验、密码加解密和响应脱敏；handler 仅解析请求并调用服务。

- `GET /api/v1/admin/config`：保留现有字段，扩展 comment.captcha、mail、revision；密码只返回 password_configured 和 password_needs_reset 标志，不返回原文或密文。
- `PATCH /api/v1/admin/config`：带 revision 与需要修改的业务分组；事务内检查 revision 后更新，过期版本返回 409。未提交的分组保持原值。
- SMTP password 省略或空字符串表示保留现有密码；非空表示替换（不 trim 密码）；clear_password=true 显式清除，并与非空 password 互斥。
- `POST /api/v1/admin/mail/test`：使用已保存的 SMTP 配置向指定收件地址发送测试邮件，发送过程最多 30 秒；错误返回脱敏的统一 AppError。
- `GET /api/v1/admin/mail/status`：只向管理员返回待发送/失败数量、最近成功时间和简化失败类别。

这些接口全部要求 AuthUser，并同步 DTO 的 ToSchema、utoipa 注解与 OpenAPI 注册。

保存前校验昵称/地址长度、邮件地址、端口、加密模式、站点 HTTP/HTTPS 地址和验证码取值。沿用现有“禁用验证码可使用零 TTL”的兼容语义；启用时 TTL/次数必须为正，PoW 难度保持现有 1..=8。后台只接受明确列出的业务字段，禁止修改部署密钥。

## 验证码与 SDK 兼容

SDK 每次提交前限时刷新验证码配置，使已经打开的页面能够跟随后台开关调整。刷新与模态框过程保留草稿，避免重复提交。

保留现有 PoW challenge 格式、前导零规则、HMAC 取钥方式、蜜罐 → PoW → 图形码 → 字段校验 → 落库顺序，以及 Redis 原子消费和图形码 Lua 校验。关闭的签发端点仍返回 404。

当前 SDK 对无验证码接口的旧服务端继续兼容；已确认支持验证码的新服务端探测暂时失败时保留草稿并提示重试。提交过程中后台改变难度/开关而导致校验失败时，重新拉取配置和验证码，用户重试即可，不自动重复 POST。

公共验证码配置响应增补 reply_notification_enabled，使 SDK 按服务端配置显示“接收回复邮件”复选框。新增提交字段 reply_notification 默认为 true，允许用户取消；旧客户端未提交此字段仍能工作。邮箱、通知偏好和发送状态不进入公共评论响应。

## SMTP 与秘密处理

使用 lettre 异步 SMTP；支持 STARTTLS（默认）、隐式 TLS，以及明确选择的无 TLS 模式用于本地中继/开发。用户名和密码同时存在时认证，无用户名时支持不要求认证的中继。

SMTP 密码使用标准 AEAD 加密后保存；加密密钥从 JWT 密钥以独立标签派生，使用随机 nonce，与验证码 HMAC 域分离。接口、日志、页面和错误均不回显密码。更换 JWT 密钥后，需要重新填写 SMTP 密码，启动保持可用，后台显示密码需要重新配置，邮件发送暂停至修复。

SMTP 默认关闭；只有启用并配置有效 SMTP 后，提醒开关才生效。测试入口由管理员主动操作，自动化测试只连接本机假 SMTP 服务，不给外部收件人发信。

## 邮件事件与可靠性

评论落库及其通知入队在同一事务中完成，SMTP 网络发送在后台任务处理，不阻塞正常评论提交。

- 新评论（顶层或回复）提交成功后，按管理员提醒开关生成一条管理员通知，包括作者、正文、页面和审核状态；蜜罐假成功和导入不会入队。
- 回复提醒只发送给直接父评论的有效邮箱；跳过未填邮箱、无效邮箱、取消提醒以及回复者与被回复者邮箱相同的情况。
- 新回复已公开时可入待发送状态；待审核回复只入等待审核状态，审核通过后变为可发送。已有旧评论/导入记录没有新提交事件，调整审核状态不会追发历史邮件。
- event_key 唯一约束确保重复审核/并发请求不会再次创建同一事件。成功发送回复提醒后更新该回复的 is_notified。
- 发送前再次检查评论与父评论仍存在、回复仍为 approved，且提醒开关仍开启；删除/标记 spam 的未发送回复被取消。

任务通过数据库条件更新领取，支持多实例工作；每次 SMTP 调用总超时 30 秒，租约 120 秒，进程退出后租约超时的任务能够重新领取。失败最多尝试 5 次，等待时间为 30/120/600/1800 秒，失败终态可在后台看到。终态任务在 30 天后清理，避免队列无界增长。

保证应用事件不会重复入队；SMTP 接受邮件后、数据库标记成功前进程崩溃的极小窗口仍可能重投，采用固定 Message-ID 减少重复。SMTP 协议无法在本应用中实现跨服务的严格恰好一次投递。

邮件使用纯文本，站点设置构建 HTTP/HTTPS 评论页面链接，配置的中文/英文语言决定固定模板。评论中的 HTML/Markdown 不解析为邮件 HTML，用户内容不能控制邮件头。

## 后台交互

沿用本地 mdui 2.1.5、原生 ES Modules 与现有 Material 3 风格，设置页按评论规则、验证码、邮件提醒组织。显示修改状态、保存中状态、校验错误与版本冲突提示；改密卡片保持可独立操作。

邮件密码框不预填，显示是否已经配置；提供明确的清除操作。SMTP 测试按钮使用已保存配置，避免测试结果与实际运行配置不同。中文/英文新增文案分别加入后台与 SDK 字典；用户值通过 DOM/textContent 渲染。
