## 已知验证边界

- 本机没有 redis-server，六项 Redis 专用测试按项目现有逻辑提前返回；内存验证码路径和队列测试实际执行。
- PostgreSQL/MySQL 未接真实数据库运行迁移和并发测试，编译与 SQL 生成检查不等同于数据库端到端验证。
- 真实邮件界面单击在最后一轮遇到浏览器自动审批超时/会话占用，未完成；真实投递由 HTTP API 与本机 SMTP 检查验证，页面交互由实际组件和接口模拟分别验证。
- 文档构建已有 caddy 高亮回退为 txt 的提示，构建成功。
- SMTP 服务器接受邮件后、数据库写回前进程崩溃仍可能重投，固定 Message-ID 仅用于减少重复；已开始发送的邮件无法撤回。

## 实施决策

- 使用当前项目的独立功能分支，保留既有工具与计划路径；未自动合并或推送。
- 最初依赖审批超时期间先完成实现，未把未执行的测试计作通过；依赖恢复后补跑实际检查并修复发现的问题。
- 旧 max_length=0、空默认昵称和 rate_limit=0 保留升级语义；编辑评论配置时要求修正正文长度与默认昵称。
- SMTP 密码解密失败仍保留密文，可继续修改其他设置；重新填写或明确清除后恢复邮件。
- 验证码 TTL 固定最多一年，避免 Redis 过期范围溢出；旧部署若设置超过一年需要先调整。
- 前端文件与邮件新模块按职责并行实现，共享 Rust 文件交接后再修改，最终统一验证。
- 回退旧程序需使用升级前数据库备份并先保留升级后的完整数据库；Sea-ORM 会拒绝旧程序不认识的新迁移记录，不能直接用旧二进制连接升级库。
